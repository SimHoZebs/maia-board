# useEffect cleanup — agreed changes (living notes)

From the review thread starting 2026-09-16. Each entry: what we agreed,
why, and status.

## Implemented

### 1. `useServerBatch`: honest gating between reconciler and starter
- Reattach is *mount reconciliation* (both workspaces, including manual
  `auto: false`); auto-start is *change submission*, Play-only in
  practice. A `persistedItemsFor(scopeKey)` helper is now the single
  definition of "the persisted job owns this mount," read by both —
  the submitter stands down on non-null, the reconciler adopts.
  A synchronously-set flag was considered and rejected: it goes stale
  across scope changes and would suppress legitimate settings-change
  resubmits. Exact guard semantics preserved (including the
  already-attached branch).

### 2. `useReview` priorFocus effect → render-phase assignment
- Read-then-write in the same beat; the position-ID guard inside
  `selectMaiaDisplay` neutralizes the concurrent-abandon concern. Ref,
  not state or Zustand: single-consumer memory, no subscribers.

### 3. P0 micro-cuts
- `ReviewCharts` wheel listener subscribes mount-once (`[]` — the
  handler never read tab state).
- `useMediaQuery` is now a `useSyncExternalStore` (memoized
  subscribe/snapshot per query): no mount effect plus corrective
  second commit.
- The openings chunk-preload effect died with the chunk (see 5).

### 4. Shared `useBulkPrime` + persistence dirty-check
- New `useBulkPrime` owns the bulk cache-restore shape (signal-abort
  only cancel path, `loadKey` restarts, nodes/settings ride refs);
  `useReview` passes its prime key + attempt with an `onSettled` that
  files the prime record, `usePlayFeedback` passes line + settings
  keys fire-and-forget. `usePlayFeedback` no longer imports `useEffect`.
- The `useMaiaBoard` persistence effect skips byte-identical payloads
  (a scrub no longer rewrites all seven keys per ply); quota errors
  still surface and unwritten keys retry next pass.

### 5. Mode ownership: explicit dispatch, no render patch
- Tab taps dispatch their mode in the click handler
  (`DestinationNav`, `MobileMenu`); Back/Forward dispatches in the
  popstate listener; the wrapper's mode branch forwards to
  `boardDispatch` without navigating (navigation is location-owned —
  navigating there double-pushes behind the NavLink). Pre-mount
  canonicalization in `main.tsx` sends unknown entry URLs to `/play`
  before the router mounts, so the first commit already names a real
  destination.
- Deleted together in `useMaiaBoard`: the render-phase mode patch, the
  every-render `current` sync (dispatch owns the ref again), and the
  request backstop (every request now flows through dispatch).
- **Flail lesson, do not reintroduce:** an eager event dispatch plus a
  location-sync backstop effect ping-pong across the NavLink commit
  boundary (click renders state-ahead-of-location, the effect
  "corrects" back, the landing corrects forward). Each null→request
  edge re-fires the engine flight: 43 browser failures, all duplicate
  `/move` POSTs. A backstop was tried and removed the same session.
  Invariant is documented at the routes: no new `<Navigate>` without
  a mode dispatch at its event.

### 6. Openings book moves server-side; client artifact deleted
- **Decision:** server owns the book completely. New `POST /openings`
  (`{initial_fen, moves}` → `{matches: [{ply, eco, name}], book_flags}`).
  Chess truth in `backend/openings_lookup.py` (python-chess, the same
  implementation already trusted for position validation); Go
  (`backend/openings.go`) owns HTTP validation + process boundary,
  mirroring `Evaluator.run`. Table is `backend/openings_table.json`
  (3810 positions, content-identical to the deleted client artifact —
  verified 0 mismatches against git history), generated by
  `frontend/scripts/build-openings-table.mjs` (`--check` wired into CI).
- Client `src/openings.ts` keeps its name and `useLineOpenings`
  signature but is now one fetch per line (lineKey cache, abort on
  navigation) plus a pure `openingAt` derivation — zero call-site
  changes. Deleted: `openings.generated.ts`, old `openings.test.ts`
  content, `scripts/build-openings.mjs`. Custom-start lines still
  return nulls, never errors.
- Browser fixtures mock `/openings` with an empty book (no test ever
  asserted chips positively). One real find: play-feedback's badge
  assertion relied on the chunk race to match exactly one badge;
  deterministic now, asserts `toHaveCount(2)`.
- **Verified:** `go vet` + full `go test ./...` green, `tsc` + 238
  vitest green, all 104 browser tests green, production build clean
  (no openings chunk). **Not verifiable on this machine** (no
  Python): `test_openings_lookup.py` — needs CI's Go-job run.
