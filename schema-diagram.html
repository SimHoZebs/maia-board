maia-board — SQLite schema

Schema version: code-managed DDL, no numbered migrations (CREATE TABLE IF NOT EXISTS + ensure* at store open; cache identity v2) · 7 tables · single SQLite file (WAL, FK pragma on)
  • Ownership: games.owner_id logically scopes rows to users.id; '' means legacy pre-user rows, claimed on login.
  • Cache bounds: evaluations_v2 capped at 25,000 rows · keys ≤ 4 KiB · values ≤ 64 KiB · oldest-rowid-first eviction; games never evict.
  • Singletons: one user_current row per user (resume marker); no global state tables remain.
  • Dedupe: partial UNIQUE(owner_id, source) WHERE source <> '' — per-owner Lichess re-imports skip instead of duplicating.
  • Memory only: batch review jobs live in server RAM; only finished plies persist into evaluations_v2.
